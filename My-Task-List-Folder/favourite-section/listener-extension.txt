**Event Listener (EventSubscriber)** နှင့် **Twig Extension** တို့ကို ဘာကြောင့် သုံးရသလဲ၊ ၎င်းတို့ (၂) ခုသည် မဖြစ်မနေ တွဲသုံးရန် လို/မလိုနှင့် အတွေ့အကြုံ (၆) လရှိ Junior Developer များ အလွယ်တကူ သဘောပေါက်နိုင်စေမည့် အသေးစိတ် ရှင်းလင်းချက် ဖြစ်ပါသည်။

---

### ၁။ အဓိက အမေး၏ တိုတိုရှင်းရှင်း အဖြေ (Direct Answer)

> **မေးခွန်း:** "Listener သုံးရင် Twig Extension ပါ တွဲသုံးဖို့ မဖြစ်မနေ လိုအပ်သလား?"
>
> **အဖြေ:** **လုံးဝ မလိုအပ်ပါ (No, they are independent)**။
> ၎င်းတို့ (၂) ခုသည် **လုံးဝ ကွဲပြားသော အလွှာ (Layer)** တွင် အလုပ်လုပ်ကြပြီး တစ်ခုနှင့်တစ်ခု မဖြစ်မနေ မှီခိုနေခြင်း မရှိပါ။ တစ်ခုတည်း သီးသန့် အသုံးပြုနိုင်သလို၊ လိုအပ်ချက်အရ ပေါင်းစပ်၍လည်း အသုံးပြုနိုင်ပါသည်။

---

### ၂။ Event Listener ဆိုတာ ဘာလဲ? ဘာကြောင့် သုံးသလဲ? (Backend Layer)

* **အလွှာ (Layer):** Backend / Business Logic
* **အဓိက အခန်းကဏ္ဍ:** ဖြစ်ရပ်တစ်ခုခု (Event) ဖြစ်ပျက်သွားသည့်အခါ **နောက်ကွယ်မှ အလိုအလျောက် အလုပ်လုပ်ပေးခြင်း** ဖြစ်ပါသည်။
* **နားလည်လွယ်သော ဥပမာ:** *"မနက် ၆ နာရီ Alarm မြည်သည့်အခါ လူက အိပ်ရာထသကဲ့သို့"* စနစ်ထဲတွင် တစ်ခုခု ဖြစ်သွားပါက လိုက်လုပ်ပေးခြင်း ဖြစ်ပါသည်။

#### Event Listener ကို ဘယ်အချိန်မှာ သုံးသလဲ?
1. **Favorite ထည့်ပြီးချိန်တွင် Log မှတ်လိုသည့်အခါ:**
   "User A သည် Product B ကို Favorite ထည့်လိုက်သည်" ဟု System Log ရေးမှတ်ခြင်း။
2. **Email သို့မဟုတ် Notification ပို့လိုသည့်အခါ:**
   ဝယ်ယူသူက ပစ္စည်းတစ်ခုကို Favorite ထည့်လိုက်ပါက "သင့်စိတ်ကြိုက်ပစ္စည်း စာရင်းထဲ ရောက်ရှိပါပြီ" ဟု Email ပို့ပေးခြင်း။
3. **Point ပေးလိုသည့်အခါ:**
   ပစ္စည်းတစ်ခုကို Favorite ထည့်သည့်အတွက် Point ၁၀ မှတ် လက်ဆောင်ပေးခြင်း။

> 💡 **မှတ်ချက်:** Event Listener သည် Backend အလုပ်များကိုသာ လုပ်ဆောင်ပေးနိုင်ပြီး **HTML မျက်နှာပြင် (UI) ပေါ်တွင် Button သို့မဟုတ် စာသားများ တိုက်ရိုက် သွားရောက် ရေးထုတ်ပေးနိုင်ခြင်း မရှိပါ**။

---

### ၃။ Twig Extension ဆိုတာ ဘာလဲ? ဘာကြောင့် သုံးသလဲ? (Frontend / View Layer)

* **အလွှာ (Layer):** Frontend / View Template (Twig)
* **အဓိက အခန်းကဏ္ဍ:** HTML Template (`.twig`) ဖိုင်များအတွင်း **ဒေတာတွက်ချက်ခြင်းနှင့် စစ်ဆေးမှုများ ပြုလုပ်နိုင်ရန် Helper Function အသစ်များ ဖန်တီးပေးခြင်း** ဖြစ်ပါသည်။
* **နားလည်လွယ်သော ဥပမာ:** *"ဂဏန်းပေါင်းစက် (Calculator) ကဲ့သို့"* Twig ထဲတွင် PHP Logic များကို အလွယ်တကူ ခေါ်ယူ တွက်ချက်ပြသနိုင်အောင် ပြုလုပ်ပေးခြင်း ဖြစ်ပါသည်။

#### Twig Extension ကို ဘယ်အချိန်မှာ သုံးသလဲ?
1. **Template ထဲတွင် အခြေအနေ စစ်ဆေးလိုသည့်အခါ:**
   `{% if is_favorite(Product) %}` ဟု ရေးပြီး User က Favorite လုပ်ထားလျှင် အနီရောင်ခလုတ်၊ မလုပ်ထားလျှင် ရိုးရိုးခလုတ် ခွဲပြသခြင်း။
2. **အရေအတွက် တွက်ချက်ပြသလိုသည့်အခါ:**
   `{{ favorite_count(Product) }}人が登録中` ဟု ရေးပြီး အခြား User ဘယ်နှစ်ယောက် Favorite လုပ်ထားသလဲကို HTML ပေါ်တွင် Badge အဖြစ် ဖော်ပြခြင်း။
3. **Format ပြောင်းလဲလိုသည့်အခါ:**
   ငွေကြေး၊ ရက်စွဲ၊ သို့မဟုတ် စာသားများကို Template ထဲတွင် လှပအောင် ပြင်ဆင်ပြသခြင်း။

> 💡 **မှတ်ချက်:** Twig Extension သည် HTML ပေါ်တွင် ဒေတာပြသရန်သာ ဖြစ်ပြီး၊ User ခလုတ်နှိပ်လိုက်ချိန်တွင် နောက်ကွယ်မှ Database ထဲ သိမ်းဆည်းခြင်း သို့မဟုတ် Email ပို့ခြင်း စသည့် Event များကို သူကိုယ်တိုင် တိုက်ရိုက် မလုပ်ဆောင်နိုင်ပါ။

### ၄။ Listener နှင့် Twig Extension နှိုင်းယှဉ်ချက် (Comparison Table)

| အချက်အလက် | Event Listener (EventSubscriber) | Twig Extension |
| :--- | :--- | :--- |
| **အလုပ်လုပ်သည့် နေရာ** | Backend Controller / Database / Service | Frontend Twig Template (`.twig`) |
| **အလုပ်လုပ်သည့် အချိန်** | User တစ်ခုခု လုပ်ဆောင်လိုက်ချိန် (ဥပမာ- ခလုတ်နှိပ်၍ Form Submit ဖြစ်ချိန်) | စာမျက်နှာကို စတင် Render လုပ်ပြီး HTML ပြသချိန် |
| **အဓိက ရည်ရွယ်ချက်** | လုပ်ဆောင်ချက်တစ်ခု ပြီးဆုံးချိန် နောက်ကွယ်မှ Reaction ပေးရန် (Action Trigger) | Template ထဲတွင် Function အသစ်များ ခေါ်သုံးနိုင်ရန် (UI Helper) |
| **ဥပမာ Code** | `$logger->info('Favorite Added');` | `<span>{{ favorite_count(Product) }}</span>` |
| **မဖြစ်မနေ တွဲသုံးရမလား?** | **မလိုပါ** (သီးခြားစီ သုံးနိုင်သည်) | **မလိုပါ** (သီးခြားစီ သုံးနိုင်သည်) |

### ၅။ လက်တွေ့ ဥပမာ ၃ မျိုးဖြင့် ခွဲခြားနားလည်ခြင်း (Practical Scenarios)

#### 📌 Scenario A: Event Listener သီးသန့် သုံးရမည့် အခြေအနေ (Twig Extension မလိုပါ)
* **Client လိုအပ်ချက်:** *"User တွေ Favorite ထည့်တိုင်း Admin ထံ စာရင်း Log မှတ်ပေးပါ"*
* **ဖြေရှင်းပုံ:** UI မျက်နှာပြင်တွင် ဘာမှ အသစ်ပြစရာ မလိုသဖြင့် **Event Listener (`FavoriteEventListener`) သီးသန့်** ရေးသားရုံဖြင့် လုံလောက်ပါသည်။

#### 📌 Scenario B: Twig Extension သီးသန့် သုံးရမည့် အခြေအနေ (Listener မလိုပါ)
* **Client လိုအပ်ချက်:** *"Product List စာမျက်နှာမှာ ပစ္စည်းတစ်ခုချင်းစီကို Favorite လုပ်ထားတဲ့ လူဦးရေ `{{ favorite_count(Product) }}` ပြပေးပါ"*
* **ဖြေရှင်းပုံ:** ဒေတာကို ဆွဲထုတ်ပြသရုံသာ ဖြစ်ပြီး Event အသစ် မဖမ်းယူသဖြင့် **Twig Extension (`FavoriteTwigExtension`) သီးသန့်** ရေးသားရုံဖြင့် လုံလောက်ပါသည်။

#### 📌 Scenario C: နှစ်ခုစလုံးကို အတူတွဲသုံးသည့် အခြေအနေ (Full Feature)
* **Client လိုအပ်ချက်:**
  1. Product List တွင် Favorite အရေအတွက် Badge ပြသလိုခြင်း 👉 **Twig Extension** ဖြင့် လုပ်ဆောင်သည်။
  2. Favorite ထည့်ပြီးပါက အကြောင်းကြားစာ ပို့ခြင်း၊ Log မှတ်ခြင်း 👉 **Event Listener** ဖြင့် လုပ်ဆောင်သည်။

* **စနစ်အတွင်း လုပ်ဆောင်ချက်တစ်ခု ပြီးဆုံးသွားချိန် နောက်ကွယ်မှ Logic တစ်ခုခု အလိုအလျောက် ပတ်သက်လုပ်ဆောင်လိုလျှင်** 👉 **Event Listener** ကို သုံးပါ။
